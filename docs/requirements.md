# 赛博小镇需求文档

## 1. 目标与使用者

让想体验 AI 角色交互的用户通过一个网址进入像素办公室，无需安装游戏客户端。核心流程：进入办公室 → 走近同事 → 交谈 → 观察记忆与关系变化 → 再次访问继续进度。

界面、提示和文档使用简体中文。视觉呈现轻松、有生活感的像素办公室；游戏场景为主体，说明和状态不应遮挡主要活动区域。

## 2. 功能需求

### R01 办公室与移动

- 提供工作区、家具与三位 NPC 的 2D 像素场景。
- 支持 WASD、方向键、触屏移动；不能穿越阻挡家具或离开场景。
- 接近 NPC 时显示交互提示，按 E 或点击交互控件开始对话。
- 输入框获得焦点时，快捷键不得干扰输入。

验收：键盘和触屏均可到达三位 NPC，边界与家具碰撞有效，输入消息时角色不意外移动。

### R02 独立角色与对话

| ID       | 姓名 | 职业          | 交互方向                       |
| -------- | ---- | ------------- | ------------------------------ |
| engineer | 张三 | Python 工程师 | 严谨直接，关注实现与代码质量   |
| product  | 李四 | 产品经理      | 善于倾听，关注用户需求与取舍   |
| designer | 王五 | UI 设计师     | 注重细节，关注色彩、排版与体验 |

- 三位角色分别拥有独立历史、记忆和关系。
- 发送消息后展示等待状态并阻止重复提交；成功显示回复，失败显示原因并允许重试。
- 无模型配置时使用规则演示，始终明确显示模式；有配置时由服务端请求 OpenAI 兼容接口。
- AI 请求失败不能悄悄改用演示回复，不能把失败计为成功互动。

验收：角色历史相互隔离，服务异常可见，模式可区分，浏览器中看不到模型密钥。

### R03 记忆与存档

- 短期上下文保留最近 10 条消息，超过 120 分钟的消息不作为短期上下文。
- 每位 NPC 最多保留 200 条长期记忆；按文本相关度检索，最多使用 5 条。
- 有效对话、记忆与关系保存到当前浏览器 localStorage，刷新后恢复。
- 空存档、损坏存档与存储不可用不应导致页面无法进入。

验收：介绍姓名或喜好后可再次回忆；其他角色不能自动获知；刷新后保留正常存档。

### R04 好感度

| 分数   | 等级 |
| ------ | ---- |
| 0–20   | 陌生 |
| 21–40  | 熟悉 |
| 41–60  | 友好 |
| 61–80  | 亲密 |
| 81–100 | 挚友 |

- 单次变化限制为 -5 至 +5，最终分数限制为 0 至 100。
- 当前关系等级参与回复生成，影响角色的亲近程度。
- 界面展示当前关系和变化；演示采用可解释规则，AI 模式由模型分析情感并由服务端限制范围。

验收：友好、普通和不友好的消息能触发适当变化，边界分数不越界。

### R05 背景活动

- NPC 未对话时展示背景状态或台词。
- AI 模式一次请求批量生成三位角色的背景台词；演示模式使用规则台词。
- 更新由网页发起，不依赖 Vercel 中的永久循环任务，避免高频模型调用。

验收：未打开聊天也能看到状态，背景更新不阻断对话。

### R06 日志

- 页面展示互动事件、关系变化与错误，支持导出日志。
- 服务端只记录必要元信息，不默认记录密钥或完整聊天正文。
- 导出数据可能包含用户输入，应由用户保管。

### R07 发布与可用性

- Vercel 同站点运行首页与 `/api/*`；无密钥可体验演示。
- 添加模型配置并重新部署后可使用真实 AI。
- 电脑和手机布局可用，按钮文字清楚，焦点可见，状态不只靠颜色表达。
- 支持可选访问口令，降低公开模型调用被滥用的风险。

## 3. 不在本期范围

- 多人联机、账户系统、跨设备云存档、管理后台。
- NPC 自主日程、持续自主对话、任务与经济系统。
- 向量数据库、外部数据库迁移、WebSocket 服务。
- 防作弊：本地关系状态不能用于奖励、收费或权限判定。

## 4. 平台适配边界

本项目以 Canvas 替代 Godot 客户端，以 Vercel Node.js Functions 替代常驻 Python 服务，保留角色对话、记忆、关系、场景交互和日志的主流程。运行引擎与持久化方式不同，不声称技术实现完全一致。

真实 AI 验收依赖有效密钥、网络、账户额度和模型权限。未配置密钥时，只能验收演示逻辑，以及用模拟请求验证模型接口处理。
