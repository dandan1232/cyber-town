# 部署与配置

## 1. 首次体验

不配置模型密钥也可发布演示模式。规则回复用于体验角色交互、记忆、关系和日志，不产生模型调用费用；页面明确显示当前模式。

## 2. 本地运行

```bash
npm install
npm run dev:full
```

打开终端显示的网址。`npm run dev` 主要用于网页开发，完整对话需要本地 API 服务。

发布前执行：

```bash
npm test
npm run build
```

## 3. 发布到 Vercel

1. 使用有权访问仓库的账号登录 Vercel。
2. 新建项目，导入 GitHub 的 `cyber-town` 仓库。
3. 使用 Vite 预设，构建命令 `npm run build`，输出目录 `dist`，保留仓库中的 Vercel 配置。
4. 选择与项目要求一致的受支持 Node.js 版本。
5. 首次可以不设置模型变量，直接部署。
6. 打开实际部署地址，验证首页、`/api/status` 和一轮演示对话。

构建成功不等于公网验收成功。若项目启用了 Vercel 访问保护，访客可能仍需登录；希望任何人点击即可打开时，应检查生产域名的访问设置。

机器已有 Vercel 登录态时，也可从仓库运行：

```bash
npx vercel --prod
```

首次项目绑定以平台实际提示为准。上线链接必须采用平台实际返回的地址，不应猜测域名。

## 4. 模型配置

在 Vercel 项目的 Environment Variables 中设置服务端变量，再重新部署：

| 变量             | 用途                     | 填写建议                            |
| ---------------- | ------------------------ | ----------------------------------- |
| `LLM_API_KEY`    | 模型密钥                 | 只存服务端，禁止提交 Git            |
| `LLM_BASE_URL`   | OpenAI 兼容 API 基础地址 | 按供应商说明填写，通常以 `/v1` 结尾 |
| `LLM_MODEL`      | 模型名称                 | 使用账户有权限调用的模型 ID         |
| `APP_ACCESS_KEY` | 可选访问口令             | 启用付费模型时建议设置              |

禁止使用 `VITE_` 前缀存放密钥，避免进入前端产物。不要把密钥放进聊天输入、提交信息或错误截图。

重新部署后检查状态并发送一条真实消息。AI 模式仅表示已配置，不能证明供应商额度、网络和模型权限正常，必须以实际调用验证。

## 5. 可能需要用户最终补充的配置

| 项目                     | 是否必需        | 缺少时的影响               |
| ------------------------ | --------------- | -------------------------- |
| Vercel 登录与仓库授权    | 发布时需要      | 无法创建真实部署           |
| 模型密钥、地址与模型名   | 真实 AI 需要    | 仍可运行演示模式           |
| 访问口令与供应商消费限额 | AI 公网访问建议 | 更难控制未经授权调用与费用 |
| 自定义域名               | 可选            | 默认平台地址即可访问       |

不需要预先建立云数据库。本版本存档仅保存在本浏览器，不支持跨设备同步。

## 6. 排查问题

- 首页正常但聊天失败：检查完整本地服务是否运行，或生产 `/api/*` 函数是否部署成功。
- 配置后仍显示演示：检查变量是否作用于当前部署环境，并重新部署。
- AI 调用失败：检查模型 ID、供应商额度、密钥权限及基础地址，通过服务端错误定位。
- 别人打不开链接：确认分享的是生产地址，检查 Vercel 访问保护。
- 更换设备或清除数据后没有进度：浏览器存档不会自动同步，清除站点数据会删除进度。
- 日志导出不是完整存档备份，不能据此承诺恢复游戏进度。
